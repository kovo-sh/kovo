Section 1

Executive architecture & design thesis

Kovo is a defensive web-application security verifier. It finds vulnerabilities in authorized targets, proves them with host-verified evidence, and re-tests patches. v8 targets deep multi-hop causal chains (3–6 hops) across multi-service SaaS, where each endpoint looks fine alone and the impact only shows up when the steps are combined.

The LLM is a cheap, creative, untrusted hypothesis generator. The host is an expensive, boring, trusted proof kernel. Nothing the model says counts as evidence.

Prompt injection is assumed

Target responses are attacker-controlled text that goes straight into model context. We make injection harmless instead of trying to prevent it: the model never holds a credential, can't reach a host outside the grant, and can't forge a receipt.

Fabricated confirmation is the expensive failure

The release gate is 100% worst-run precision. Stdout, model summaries and declarative specs are never evidence. Confirmation is re-derived from the host-signed transcript, twice, with fresh nonces.

Ephemeral workers, durable graph

Containers are disposable. The causal attack graph (CapabilityLedger) and the v8.hop_checkpoint.v1 briefs live on the host in SQLite WAL, so a timed-out worker loses its turns but not its progress.

Section 3

End-to-end scan lifecycle

Phase 0: Recon

phase0-recon.ts extracts routes from framework patterns, JS request shapes, tRPC, specs and manifests. exec-recon-planner.ts turns them into lanes. Checkpoint 'phase0'.

Phase A: code-first + floor

It is blocking and wall-clock capped, with a split request budget (resolvePhaseRequestBudgets; no borrowing). buildStaticWorkspaceSnapshot does one walk and builds ProgramGraph once, with zero model turns. code_audit suspects → settleCodeAuditSuspects. ExecFloorLane runs the deterministic --no-llm floor.

Phase B: dynamic scheduler

FrontierWaveController over frontier-scheduler.ts: beam depth 1..6, width 8..16, ranked by EVI. Chain hypotheses interleave with route sweeps. Wall-clock settlement exports v8.hop_checkpoint.v1 (≤2 KB, handles only) to seed the next assignment.

Layer 3: dual clean replay

verifyScript runs the kovo_verify.ts script twice in fresh VerifyRpcServer sessions with fresh nonces. Both oracles, both signatures and causalFingerprints must agree.

Confirm + dedupe

verifyCompositeReceipt for chains, verifyReceipt for single findings. evaluateSubmissionDedupe = structural computeFindingFingerprint + a semantic judge that only suppresses duplicates and never confirms.

Patch verification

generateAndReviewPatch → retestCompositeChainPatch replays each hop against the patched lab and records which causal edge broke (CompositeBrokeCausalEdge), sealed by computeCompositeRetestProofDigest.

Section 5

  
Wire protocol: worker ↔ VerifyRpcServer

  
The protocol is HTTP over a Unix-domain socket that is bind-mounted into the container at /kovo-rpc. The SDK reads the token from
  KOVO_RPC_TOKEN_FILE, sends it as x-kovo-rpc-token, and echoes the attempt nonce (KOVO_VERIFY_NONCE) in x-kovo-verify-nonce.
  The proof document is written to KOVO_PROOF_RESULT_FILE with the marker KOVO_PROOF_RESULT:.
