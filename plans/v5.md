## 1. Executive Summary & Empirical Motivation

Kovo Hunter v4 built strong defensive foundations: an isolated zero-trust scope broker, persistent Playwright sessions, 14 differential probe classes, 14 Zero-LLM `ReplaySpec` verifiers, an offline `--network none` multi-engine SAST worker, 7 specialist worker profiles, and a multi-container `LabRunner`.

However, a full 5-stream codebase and benchmark audit revealed **why real-world vulnerability recall remains far below Kovo Hunter's architectural ceiling**:

1. **Empirical Baseline (`.kovo/benchmarks/kovo.sqlite`):**
   - Stored `held-out-saas` run (`20` planted vulns, `6` hard decoys):
     - Funnel: `20 targets → 18 surfaceDiscovered → 13 hypothesisFormed → 2 signalObserved → 0 specSubmitted → 0 zeroLlmConfirmed` (`0` FPs).
     - Failure taxonomy: `trigger_miss: 10`, `hypothesis_miss: 5`, `surface_miss: 2`, `replay_spec_miss: 2`, `csrf_blocked: 1`.
2. **Benchmark Blind Spot ([scripts/benchmark-live.ts](../scripts/benchmark-live.ts)):**
   - `npm run benchmark:recall` bypasses Kovo Hunter's production agentic orchestrator ([execution.ts](../src/server/execution.ts), [agent-session.ts](../src/server/agent-session.ts), [semantic-audit.ts](../src/server/semantic-audit.ts)) and drives a procedural script (`benchmark-env` → `benchmark-probes` → `benchmark-specs` → `replay-verifier`) directly. As a result, critical production wiring defects inside `Execution` went undetected.
3. **Production Disconnections ("Built in v4, Inert in Real Runs"):**
   - `Execution` silently drops v4 broker/browser arguments (`session`, `csrfBind`, `authMutation`, `traceId`, `runId`, `assignmentId`) and never attaches `storage` to `RequestBroker`/`ScopedBrowser`/`Grant`, leaving second-order canary scanning completely inert.
   - `endpoint_params`, `api_dependencies`, and `updateEndpointCoverage()` are write-only dead plumbing; `normalizeRouteTemplate()` clobbers `:orgId`/`:invoiceId` → `:id` and lowercases paths.
   - `dedupe.ts` omits 3 of 14 v4 `ReplaySpec` kinds (`auth_protocol_proof`, `cache_differential`, `sql_time_diff`), collapsing distinct findings onto `'/'`.
   - `routeStepToSpecialist` regex order hijacks auth/header steps into `protocol-cache-edge-specialist`; 4 of 7 specialist profiles reference nonexistent skill slugs; Phase-3 `reasoning` refinement is unreachable after inline verification failures.
   - The compiled Nuclei template corpus stops at **2020** (0 CVEs from 2022–2024), `generic` appliance templates consume **57 of 60** slots on an Express target, `cve-broker.ts` never checks semver `affectedRange`, `isUnguardedPath` conflates auth guards with input sanitizers, Stage-1 LLM semantic spec generation is hardcoded off, and Patch Gate 6 (`dynamic_retest`) is unwired yet reports `passed: true`.
4. **Real-World Coverage Gaps vs. `benchmarks/realistic-bench/` (78 Sites Across 3 Multi-Tenant Apps):**
   - Across `acme-saas` (28), `shopflow` (26), and `opsportal` (24) — `53` High/Critical, `24` Medium, `1` Low, `23` decoy-eligible:
     - **Authz (`bola`/`idor`/`bfla`/`graphql_bola` = 15 sites, 19%)** is the #1 category, heavily dependent on opaque object-ID harvesting and write-path (`cross_tenant_write`, 4 sites) + privilege-escalation (4 sites) verification.
     - **Business Logic & Workflow Bypass (10 sites, 13%)**, **CSRF State-Change (3 sites)**, **Webhook HMAC Forgery (3 sites)**, and **General Open Redirect (3 sites)** lack dedicated differential probes or zero-LLM verification primitives.
     - Real-world friction (rotating CSRF tokens, subdomain cookies, SPA `document.cookie` & `localStorage` Bearer JWTs, 401 expiry, soft-404 catch-alls, dynamic timestamps/nonces, multi-step race setup) causes cascading funnel drop-offs.

**Kovo Hunter v5's Goal:** Close every broken production wire, activate the state graph and SAST→DAST bridge, expand differential probes & zero-LLM verifiers to cover modern real-world vulnerability classes with near-zero decoy false positives, and measure every gain end-to-end against `realistic-bench` (dev seeds for hill-climbing, salted held-out seeds for anti-overfitting validation).

## 2. Preserved Non-Negotiable Defensive & Safety Invariants

Every v5 change **MUST** uphold Kovo Hunter's existing zero-trust invariants (verified by `tests/v4-boundaries.test.ts` + new `tests/v5-boundaries.test.ts`):

1. **Zero-LLM Proof Standard:** Runtime findings achieve `confirmed` (`runtime_confirmed`) **only** through deterministic `ReplayVerifier` execution (never LLM self-attestation). Static-only findings remain strictly `static_verified`.
2. **Scope & Egress Containment:** All live HTTP/browser/WebSocket traffic flows exclusively through `RequestBroker` / `ScopedBrowser` against operator-approved origins with private-IP/metadata SSRF guards; loopback targets require `KOVO_ALLOW_LOCAL_LAB=1`.
3. **Non-Destructive Verification Only:** Destructive SQL/shell/file/webshell denylists, bounded canary verification, reversible write-path checks (with cleanup), and RPS caps remain enforced at the broker layer.
4. **Offline Worker Sandbox:** All SAST/AST/call-graph/SCA workers continue executing inside `--network none`, `--read-only`, `--cap-drop ALL`, `UID 10001` containers.
5. **Secret & Credential Hygiene:** Persona credentials, rotated cookies, CSRF tokens, JWTs, and API keys are never leaked to LLMs, logs, or reports; dynamic redaction covers all rotated and mutated token surfaces.
6. **Zero Benchmark Hardcoding:** All v5 improvements must be general-purpose engine upgrades — zero app/route/param/canary hardcoding for `xben-25`, `held-out-saas`, or `realistic-bench`. Generalization is enforced via salted held-out `realistic-bench` seeds (`>= 1_000_000`).

### Milestone M3 — Real-World Probe & Zero-LLM Verifier Expansion

**Objective:** Close the remaining capability gaps revealed by `realistic-bench` (CSRF state-change, webhook HMAC forgery, general open redirect, write-path BOLA/IDOR, multi-step race conditions, business-logic/workflow invariants, and verification noise sensitivity).

#### 3.1 New Differential Probe Classes (`surface-engine.ts`) & Verifiers (`replay-spec.ts`, `replay-verifier.ts`)
1. **`csrf_state_change` (CWE-352):**
   - *Probe & Verifier:* Given a cookie-authenticated mutating endpoint (`POST`/`PUT`/`PATCH`/`DELETE`), record baseline state via a read step → replay the mutation **without** any CSRF header/body field and with a foreign `Origin: https://untrusted.invalid` / absent `Referer` (reusing only the victim session cookie) → execute a follow-up read step proving the target state actually changed (and optionally restore state). Hard decoys that return `200` without mutating or enforce `Origin`/CSRF checks fail cleanly (`0` FPs).
2. **`webhook_signature_audit` (CWE-345):**
   - *Probe & Verifier:* Identify webhook receiver endpoints (via route/param/header hints such as `x-hub-signature*`, `stripe-signature`, `x-webhook-signature`, `x-signature*`).
