# Guardian v7 — Real-World Conversion & White-Box-First Verification

Status: draft (planning), 2026-11-23, refreshed with the adopted smoke battery and certification protocol. v6 remains the shipped baseline until v7 M0 passes its gates. **Nothing in this plan is a measured v7 result.**

## Thesis

v6 fixed the architecture: three layers, an always-on deterministic floor, a hard Layer-1 boundary, and script-based proof with an independent transcript oracle. v7 adds **no fourth layer**.

**v7 is about converting wired plumbing into confirmed real-world findings, then operating it safely and repeatedly.** White-box-first analysis and realism conversion come before SaaS/plugins/multi-tenancy.

Explicitly deferred (decided, not postponed-by-accident): **continuous scheduled scanning** with a persistent org asset+code graph and PR-diff scanning. See [Deferred decisions](#deferred-decisions).

## Certification protocol (adopted)

Sequential. Each step must be green before the next is spent.

1. **M0 first.** Floor 0-spread re-gate on the post-retirement tree + legacy fixtures + `worker-gate.sh`. If the floor moves or spread > 1, stop.
2. **3-app 600 s smoke.** All three apps, ample budget, one cell each. Purpose: prove the aggregate shape before paying for repeats. Gate: **100% precision on every cell**, no lost floor targets, ≥ +2 net per app where the floor leaves room, 0 worker failures, 0 decoy/unmatched.
3. **n=3 certification matrix.** `scripts/certify-phase1.ts`: n=3 independent runs per app on dev seed 1, n=2–3 per app on salted held-out; gate on **median [min–max]**; **worst-run precision 100%**; floor spread ≤ 1 (target 0); preservation ≥ 0.95; median incremental lift ≥ +10 pp dev / ≥ +8 pp held-out.
4. **Separate long-horizon precision check.** One 45-min endurance cell is a **precision diagnostic, not a certification cell**. It may run in parallel with step 3 but cannot substitute for the 600 s cells, and a 45-min recall win does not count toward the lift gate until its unmatched claims are triaged to zero.

Rules:
- A run with any unmatched/decoy FP is **not** certifiable, regardless of recall.
- Report `provenance: floor | agent_only | chain_from_floor`; compute incremental lift from agent-only/chain findings, not `total − floor`.
- Always report **both** product numbers (`--no-llm` floor, agentic increment) on dev **and** salted held-out. Harness/procedural numbers are secondary.
- Do not quote a per-app lift as an aggregate; do not quote a wiring pass as a capability result.

## Smoke battery (adopted, replaces ad-hoc smoke runs)

~85–90% of changes are covered by a **~6 min / ~$1** Tier-1 battery if smoke is decoupled from "a smaller 45-min scan". Use it between tweaks; Tier 2 at batch boundaries.

| Tier | Budget | Contents |
|---|---|---|
| **Tier 0** | < 90 s, $0 | `scripts/worker-gate.sh` + deterministic replay of past FP/over-claim archetypes through verifier → dedupe → scheduler |
| **Tier 1** | ~6 min, ~$1, 4 parallel cells | Paired lift from post-floor snapshots (acme); rotating second app; **pre-exhausted precision trap must confirm 0**; one realism conversion micro-slice (async OOB / staging race / 4-hop) |
| **Tier 2** | 30–45 min | Cold 3-app dev n=3 + salted held-out n=2 + one 45-min endurance + realism + xben/held-out |

Tier-1 gates: 100% precision on lift cells **and 0 on the trap**; paired net-new non-regression (allow −1 only with a conversion gain plus a clean rerun); conversion drop ≤ 10 pp; 0 crashes / 0 worker failures / 0 orphans; p50 assignment ≤ 75 s and ≥ 12 completions per 300 s; ≤ $0.80 per cell. Rotate the second app each batch. Fix general invariants, never trap-specific fixtures.

**Calibration (accepted, ~$22–24, deferred until M0 lands):** 8 varied builds vs one full reference. Trust the battery only at Spearman ≥ 0.75, 100% directional agreement for Δ ≥ 2 targets, and a trap that catches every variant below 95% precision. Until then Tier 1 is a regression tripwire, not a predictive score.

Known blind spots that stay in Tier 2: cold Phase-A→B integration, and multi-hour DB drift. Rejected: bootstrap CIs (too noisy at 22 targets), frozen LLM-turn VCR (plumbing only, never recall).

## M1 — Realism and conversion (reprioritized 2026-11-24 by the held-out funnel)

The 5-stage held-out funnel (`plans/HELDOUT-LIFT.md`) reordered M1. Hypothesis coverage is **not** the binding constraint: 23 of 34 floor-missed targets were requested on the correct mounted route, but only **4 submitted a spec** (`no_spec_submitted` 19). So M1 starts with proof submission and proof grounding, not with more probing.

1. **Proof submission is the first M1 gate (P0).** A worker that reached the target route must either submit a spec or record a machine-readable `proofGapReason`; "leaning true" without either is rejected at settlement. Measure the funnel stage `verify_called / target_route_hit` on dev **and** salted held-out.
2. **Ground proofs in the target's own data.** Boolean SQLi arms must derive their base term from a benign baseline request (a hardcoded catalog term is a defect); a 401/401/401 differential is a probe-precondition failure, not a clean negative, and must bind an authenticated persona or record the gap.
3. **Dispatch completeness.** Planned ready steps must not be stranded (`stop ⇒ remainingReadyAtStop === 0` unless budget/wall/request exhausted).
4. White-box AST/dataflow slices injected into Tier-A briefs (#4 → 3/3 4-hop), now with the 3-number funnel (`dispatched`, `target_route_hit`, `verify_called` vs `oracle_rejected_by`) so brief depth and proof conversion are separable.
5. H2 race + workflow dispatch for #3 (write-BOLA/race/checkout) — **capability PASS 2026-11-24**; keep as a regression gate.
6. #2 async OOB: async SSRF + XXE **confirmed** (2 TP / 0 FP); remaining gaps are blind SQLi and the exfil chain leg 3/3.
7. Pooled OIDC/CDN SPA + hybrid HTTP→browser ProofReceipt for #1.
8. LabRunner YAML/Docker-network proxy retained; delete regex route extractors, 1-hop binding, old Compose parser/proxy.

Gate: #1–#4 **≥75% confirmed capability recall**, 100% precision; #2 `oob_wiring_fnr` ≤5% (separate from `fixture_capability_recall` ≥75%); #3 zero leaked entities; #4 ≥2/3 4-hop confirmed; and the proof-submission funnel shows `verify_called / target_route_hit` ≥ moderate coverage on held-out. Capability, not wiring — a wiring pass does not count.

## M3 (deferred) — Continuous org graph + PR-diff scanning

**Decision: deferred to v8, not started in v7.** Revisit only after M1/M2 gates. Rationale: capability conversion and precision are not certified yet, so a scheduling/asset-graph layer would multiply an unproven scanner; it also widens the blast radius (persistent credentials, long-lived state, PR-triggered execution) before the kill switch and tenant isolation in M4 exist. Scope if revived: persistent versioned asset/code graph, suppression feedback, PR/deploy blast-radius scanning (<5 min, <$0.50/PR).

Gate: sealed OSS held-out ≥60% at 100% precision, 0 FPs on clean negative-control apps, kill-switch/leak chaos test PASS.

## Evaluation portfolio (replaces local-benchmark hill-climbing)

1. **Frozen mechanical regression**: xben 25/25, held-out-saas 20/20 + patches, floor ≥55% at 0 spread, unified ≥ floor +10 pp, worst-run precision 100%.
2. **Realism Suite++**: #1–#4 now, #5 WAF/429 + introspection-off, #6 PR-diff later; ≥75% capability recall, 0 leaks, p99 store <10 ms.
3. **Real-world OSS/white-box corpus**: 8–10 pinned CVEs, 50/50 dev/sealed; ≥60% sealed recall, ≥95% precision, ≥80% patch retest.
4. **Reasoning + negative controls**: reason-bench (`--no-llm` 0/28 forever, agentic ≥40%), clean hardened repos 0 FPs.
5. **Contamination**: sealed held-outs only at milestone gates; CI lint forbids benchmark tokens in `src/server/`; always report TP per $1 and per 10 min.
